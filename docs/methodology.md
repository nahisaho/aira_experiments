## 2. プロンプト設計

### v4.0（Round-9）プロンプト構造

各実験プロンプトは、以下の3段階プレフィックス + ベースプロンプトで構成されます。

```
[3段階プレフィックス（約630文字）]
  ステップ1: 先行研究調査（ToolUniverse MCP使用）
    - 関連論文を5件以上検索
    - 各論文のタイトル・著者・年・DOI・主要知見を記録
    - 先行研究の課題・限界を整理

  ステップ2: 実験計画
    - 先行研究を踏まえた実験設計
    - 先行研究との差分を明確化
    - ベースライン比較対象の選定

  ステップ3: 実験実施
    - コード実装・可視化
    - report.md / paper.md の生成
    - References にDOI付き文献を含めること

[ベースプロンプト（約1,000文字）]
  研究テーマ固有の指示
```

平均プロンプト長: 1,667文字（ベースプロンプトのみの場合: 約1,037文字）

## 3. 実行手順

1. Round-9ディレクトリから100件の研究テーマ（SCI-001〜SCI-100）を読み込み
2. 各テーマについて、Playwrightでブラウザを操作しAIRAにプロンプトを送信
3. AIRAのCo-Scientistスキルが以下を自動実行:
   - ToolUniverse MCPによる学術論文検索
   - 実験コード（Python）の生成
   - 図表（PNG）の生成
   - report.md / paper.md の生成
4. 生成されたファイルをダウンロードし、メタデータを記録
5. 失敗した実験（タイムアウト等）を再実行

### リトライポリシー

- 初回実行: 100件中91件が完了、9件が失敗
- 失敗9件の `metadata.json` を削除し、同一プロンプトで再実行
- 再実行後: 全100件が完了

### 「完了」の定義

`status: 'success'` は以下の条件を満たした場合に記録されます:

- AIRAがエラーなく応答を完了した
- 所定のファイル（report.md, paper.md 等）が生成された

**以下は検証していません**:
- 生成されたPythonコードが正常に実行できるか
- 生成された図表がコードの実行結果と一致するか
- paper.md の参考文献が実在し、引用内容が正確か
- 論文中の数値・結果が科学的に妥当か
- 実データでの再現性

## 4. 評価手法

### 4.1 定量指標（自動測定）

| 指標 | 測定方法 | 測定対象 |
|------|---------|---------|
| ワークフロー完了率 | `metadata.json` の `status` フィールド | 全100件 |
| 所要時間 | Playwright の開始〜完了タイムスタンプ | 全100件 |
| 生成ファイル数 | ダウンロードされたファイルのカウント | 全100件 |
| DOI数 | `10.\d{4,}/` の正規表現マッチ | paper.md |
| インライン引用数 | `[n]` パターン + `(Author et al., YYYY)` パターン | paper.md |
| セクション数 | `## ` の正規表現マッチ | paper.md |
| 文字数 | ファイルサイズ | paper.md |

### 4.2 新規性マーカー分析（自動測定）

100本の paper.md から「新規性を主張する表層的特徴」を抽出しスコアリングしました。

> **重要**: このスコアは**科学的新規性そのものを評価するものではありません**。生成された論文が「新規性を主張するための修辞的要素」をどの程度含むかを測定した形式的指標です。

スコアリング基準の詳細は [新規性マーカー分析](novelty-report.md) を参照してください。

## 5. 既知の制約

### 実験設計上の制約

1. **シミュレーションデータのみ**: AIRAは実験データにアクセスできないため、すべてのデータ・結果・図表はAIが生成したシミュレーションまたはモックデータです。科学的発見としての価値はありません。

2. **コントロール群なし**: 人間の研究者が同じテーマで書いた論文との比較がないため、AI生成物の相対的な品質は不明です。

3. **単一実行**: 各テーマにつき1回のみの実行です。LLMの出力は確率的であるため、同一プロンプトでも異なる結果が得られる可能性があります。

4. **交絡要因**: v1.0〜v4.0の比較において、プロンプト以外の要因（モデルの状態、外部ツールの応答、サーバー負荷など）は制御されていません。バージョン間の差は「観察された相関」であり、因果関係として解釈すべきではありません。

### 評価上の制約

1. **プロンプト誘導バイアス**: プロンプトで「先行研究を引用せよ」「貢献リストを書け」と指示し、その出現をスコアリングしているため、評価は部分的に「指示遵守度」の測定になっています。

2. **引用の質は未検証**: DOI数は引用の量を示しますが、引用の正確性（正しい文献か、内容が一致するか、文脈に適切か）は検証していません。

3. **「品質」指標の限界**: 文字数・セクション数・数式数などは論文の形式を測定しますが、科学的な質（仮説の妥当性、手法の適切性、結果の信頼性）は測定できません。
