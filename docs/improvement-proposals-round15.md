# はじめに

AIRA の Round 11〜14（v3.4.3〜v3.4.8）の4ラウンド比較分析と、VM 外れ値4件の3回マルチラン実験から得られた知見に基づき、品質改善提案をまとめる。

## 分析の要約

### 4ラウンド比較（固定ベンチマーク30実験）

| メトリクス | R11 (v3.4.3) | R12 (v3.4.4) | R13 (v3.4.5) | R14 (v3.4.8) |
|-----------|-------------|-------------|-------------|-------------|
| VM avg | 26.5 | 42.0 | 54.8 | 50.2 |
| Uncited avg | 1.1 | 1.2 | 0.6 | 0.7 |
| FigOrp avg | 3.4 | 2.8 | 3.2 | 2.5 |
| FigOrp=0 | 63% | 67% | 62% | **77%** |
| Gates 4/4 | 100% | 100% | 87% | **100%** |

### マルチラン分析（外れ値4件 × 4サンプル）

| ID | R14原本 VM | 中央値 | CV% | 結論 |
|----|-----------|--------|-----|------|
| SCI-004 | 180 | 90 | 101% | 極めて不安定 |
| SCI-018 | 137 | **2.5** | 165% | **偶然の外れ値** |
| SCI-059 | 191 | 79.5 | 78% | 中程度の変動 |
| SCI-092 | 163 | 118.5 | 61% | 構造的に高VM |

### 核心的発見

1. **VM の変動係数（CV）が 61〜165%** — 単一実行のVM値は信頼性が低い
2. **Claims数とVMの相関 r=0.728** — 引用が増えるとVMも増える構造的問題
3. **中央値で補正するとR14 VM avg: 50.2→34.1（-32%）** — プロンプト最適化は有効
4. **Figure Manifest の採用率が24%** — 効果は確認済みだが浸透率が低い

# 改善提案

## P0: 評価手法の改善（最優先）

### 提案1: 3回実行の中央値でVM評価

**課題**: 単一実行のVMは LLM非決定性により CV>60% で変動する。SCI-018 のようにVM=137が偶然発生し、バージョン評価を歪める。

**対策**: 各実験を3回実行し、VM の中央値を採用する。

**実装案**:
```javascript
// run-experiments-round15.js
const NUM_RUNS_PER_EXPERIMENT = 3;

async function runWithMedian(experiment, workerId) {
  const results = [];
  for (let i = 0; i < NUM_RUNS_PER_EXPERIMENT; i++) {
    const result = await runExperiment(experiment, workerId, `run-${i+1}`);
    results.push(result);
  }
  const vms = results.map(r => r.validation.value_mismatches).sort((a,b) => a-b);
  return {
    ...results[1], // 中央値の実行結果を代表として採用
    vm_median: vms[1],
    vm_all: vms,
    vm_stddev: stddev(vms)
  };
}
```

**期待効果**: R14 VM avg 50.2 → 34.1（-32%）。偶然の外れ値を排除し、真の品質を反映。

**トレードオフ**: 実行時間が3倍（30件 × 32min × 3 = 48時間 → 2ワーカーで24時間）。外れ値のみ3回実行するハイブリッド方式も検討可能。

---

### 提案2: Claims正規化VM（VM/Claims比）の導入

**課題**: 現在のVMは絶対値。Claims=58の論文（VM=180）と Claims=10の論文（VM=22）を同列に比較するのは不公平。

**対策**: VM/Claims 比を補助指標として導入。

```
VM/Claims 比:
  ≤ 1.0 → 良好（各クレームに対して平均1つ以下の不一致）
  1.0-2.0 → 注意
  > 2.0 → 要改善
```

**R14 の VM/Claims 比分布**:
- VM/Claims ≤ 1.0: 7件 (23%)
- VM/Claims 1.0-2.0: 10件 (33%)
- VM/Claims > 2.0: 8件 (27%)
- VM=0 (Claims>0): 5件 (17%)

**期待効果**: 論文規模に依存しない公平な品質指標。引用密度向上（+53%）の副作用としてのVM増加を正しく評価できる。

## P1: プロンプト改善

### 提案3: Figure Manifest を Golden Rules に昇格

**課題**: Figure Manifest の採用率が24%と低い。現在はステップ内の指示に埋もれている。

**対策**: Golden Rules（冒頭3ルール）を4ルールに拡張し、Figure Manifest を含める。

```markdown
🏆 Golden Rules（最重要 — 必ず守ること）
1. 事前準備されたセルを必ず実行してからデータを参照
2. 数値を引用するときは必ず [cell:xxx] 形式を使用
3. Citation Ledger [cell:results-summary] を作成し、全数値を集約
4. **Figure Manifest [cell:figure-manifest] を作成し、全図の存在を確認** ← NEW
```

**期待効果**: 採用率 24% → 70%+。FigOrp=0 の割合 77% → 90%+。

---

### 提案4: Claims数の適正化ガイダンス

**課題**: Claims=58の時VM=180、Claims=13の時VM=0（SCI-004）。過剰な数値主張がVM増加を招く。

**対策**: 「重要な数値に絞って引用する」指示を追加。

```markdown
📌 引用ガイダンス:
- 主要な結果（精度、有意差、p値など）を優先的に引用
- 中間計算値やパラメータ設定値は本文に埋め込まず、セル参照で示す
- 目安: 1セクションあたり引用は5-8個が適切
```

**期待効果**: Claims数の適正化により、VM/Claims比の改善。外れ値の発生頻度を低減。

---

### 提案5: 値の転記ルール強化

**課題**: [cell:] 引用はあるが、転記時の値がセル出力と不一致（丸め、単位変換、フォーマット差異）。

**対策**: 転記時のルールを明示。

```markdown
📌 値の転記ルール:
- セル出力の値をそのまま使用（丸めない、単位を変えない）
- 例: セル出力が 0.8734 なら "0.8734" と記載（"0.87" や "87.3%" にしない）
- 百分率変換が必要な場合は、変換もセル内で行い、変換後の値を引用する
```

**期待効果**: 転記起因のVM（フォーマット不一致）を削減。

## P2: 構造的改善

### 提案6: ドメイン別プロンプト分岐

**課題**: SCI-092（社会科学テーマ）は4ラウンド通じてVM>80。自然科学と社会科学でデータ特性が異なる。

**対策**: ドメイン分類に応じたプロンプト分岐。

```javascript
function getDomainSpecificRules(domain) {
  if (domain === 'social-science') {
    return `
📌 社会科学研究の注意事項:
- 調査データの統計値は原典の表記をそのまま引用
- 効果量（Cohen's d, η²）は小数点以下3桁まで
- 感情分析スコアは正規化方法を明記
`;
  }
  // ... other domains
}
```

**期待効果**: SCI-092 のような構造的高VM実験の改善。

---

### 提案7: バリデーションのVM正規化

**課題**: 現VMは「不一致の絶対数」。論文が長いほどVMが高くなる構造。

**対策**: AIRA バリデーション API に VM/Claims 比を追加。

```json
{
  "value_mismatches": 180,
  "total_claims": 58,
  "vm_ratio": 3.1,  // NEW: VM/Claims
  "vm_grade": "C"   // NEW: A(≤0.5), B(≤1.0), C(≤2.0), D(>2.0)
}
```

**期待効果**: 品質評価の公平性向上。バージョン間比較の信頼性向上。

---

### 提案8: temperature=0 オプション

**課題**: LLM非決定性がCV 61-165%の変動を生む。ベンチマーク評価では再現性が重要。

**対策**: ベンチマーク実行時に temperature=0 を指定可能にする。

**トレードオフ**: 創造性が低下する可能性。ベンチマーク専用設定として位置づける。

**期待効果**: 同一条件での再現性確保。バージョン間差分の信頼性向上。

# まとめ

4ラウンド+マルチラン分析から、**LLM非決定性が品質評価の最大のノイズ源**であることが判明した。

最も効果的な改善は：
1. **評価手法の改善**（中央値採用、Claims正規化）— 正しく測る
2. **Figure Manifest の昇格**（採用率24%→70%+）— 確認済みの効果を最大化
3. **値の転記ルール強化**（フォーマット不一致の排除）— VM の根本原因に対処

これらを Round 15 で実装・検証する予定である。
