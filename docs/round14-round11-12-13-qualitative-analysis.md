# プロンプト最適化の内容（R14）

R11〜13 の定量分析から導出した改善施策：

## 1. Golden Rules（冒頭3ルール）

プロンプト冒頭に最重要ルールを配置し、LLMの注意を確保：

```
🏆 Golden Rules（最重要 — 必ず守ること）
1. 事前準備されたセルを必ず実行してからデータを参照
2. 数値を引用するときは必ず [cell:xxx] 形式を使用
3. Citation Ledger と Figure Manifest を作成
```

## 2. Citation Ledger（`[cell:results-summary]`）

全ての引用可能な数値を1つのセルに集約し、paper.md からの引用一貫性を向上：

```python
# [cell:results-summary]
summary = {
    "metric_A": computed_value_A,
    "metric_B": computed_value_B,
    ...
}
```

**採用率**: 23/29 = **79%** ✅

## 3. Figure Manifest（`[cell:figure-manifest]`）

生成した全図の存在チェックを明示的に実施：

```python
# [cell:figure-manifest]
import os
figures = ["figure1.png", "figure2.png", ...]
for f in figures:
    print(f"{f}: {'EXISTS' if os.path.exists(f) else 'MISSING'}")
```

**採用率**: 7/29 = **24%**（改善の余地あり）

## 4. NatureLM / GALACTICA 直接呼び出し

ToolUniverse 経由ではなく、MCP ツールを直接呼び出す指示に変更。

## 5. ステップ統合

5ステップ → 4ステップに統合し、report.md をオプション化。

# 考察

## プロンプト最適化の効果まとめ

### ✅ 明確な改善

1. **FigOrp が4ラウンド中最良**（avg 2.5、FigOrp=0 が 77%）
   - Figure Manifest の指示が図の孤立問題を大幅に改善
   - R11〜13 で一貫していた「0 か 4+」の二極化パターンが緩和

2. **Gates 完全回復**（100%）
   - R13 のAPIアノマリー4件がR14で全て解消
   - v3.4.8 のバグ修正とプロンプト最適化の複合効果

3. **引用密度 +53%**
   - Golden Rules の引用ルールが浸透
   - 語数削減と引用数増加の両方が寄与

4. **実行時間 -8%**
   - ステップ統合（5→4）と report.md オプション化の効果

### ✅ やや改善

5. **VM avg が初めて反転**（54.8→50.2、-8.4%）
   - R11→R12→R13 の上昇トレンドが R14 で止まった
   - 54% の実験で VM が改善（14/26）

6. **Uncited 高水準維持**（avg 0.7、Uncited=0 が 77%）
   - R13 の改善を R14 でも維持

### ⚠️ 残存課題

7. **VM 100+ が4件**（SCI-004:180, SCI-018:137, SCI-059:191, SCI-092:163）
   - 外れ値は依然として発生
   - LLM の非決定性による変動が大きい

8. **Figure Manifest 採用率が 24%**
   - プロンプト内の指示位置を上げる、または具体例を追加する必要あり

9. **VM の不安定パターン**
   - 同一実験で R11=0→R14=180（SCI-004）のような極端な変動が発生
   - 単一ラウンドのメトリクスだけでは品質を判断できない

## バージョン効果 vs プロンプト効果の分離

R14 は「v3.4.8（バージョン変更）+ 最適化プロンプト」の二重変更であるため、効果の分離は困難。ただし：

| 指標 | バージョン効果の可能性 | プロンプト効果の可能性 |
|------|---------------------|---------------------|
| Gates 回復 | 高（v3.4.8 バグ修正） | 低 |
| FigOrp 改善 | 低 | **高**（Figure Manifest） |
| 引用密度向上 | 低 | **高**（Golden Rules） |
| VM 反転 | 中 | 中（Citation Ledger） |

FigOrp と引用密度の改善はプロンプト最適化に帰属できる可能性が高い。

## 4ラウンドから見える構造的知見

### 1. プロンプトは Uncited と FigOrp に効く

Uncited と FigOrp はプロンプト変更に対する応答性が高い。これは「明確な行動指示」（引用を付ける、図の存在を確認する）がLLMに伝わりやすいためと考えられる。

### 2. VM はプロンプトだけでは解決できない

VM avg は R11(26.5)→R14(50.2) でまだ R11 を大きく上回る。VM はバリデーションロジックの精度、エージェントの値フォーマット、セル出力の取得方法など、システム全体の整合性に依存する。

### 3. LLM の非決定性が最大のノイズ源

4ラウンドを通じて、同一実験の VM が 0→180→0→180 のように振れるケースがある。温度パラメータ (temperature > 0) による出力のバリアンスが、バージョン間差分を上回ることがある。

### 4. ベンチマーク手法は信頼できる

論文構造（セクション数、テーブル数）は4ラウンドで安定しており、ベンチマークとしての一貫性は確認済み。
