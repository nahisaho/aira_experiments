# AIRA を活用した AI for Science ベストプラクティス

> 100本の科学実験ベンチマークから得られた、AIによる研究支援の実践ガイド

## はじめに

本文書は、AIRA (AI Research Assistant) を用いて100本の科学実験を自動実行した経験から得られた、AI for Science のベストプラクティスをまとめたものです。4回のイテレーション（v1.0〜v4.0）を通じて、プロンプト設計・実験管理・品質評価の各側面で蓄積した知見を体系化しています。

### 前提: AIの役割を正しく理解する

本ベンチマークの[新規性マーカー分析](novelty-report.md)が示すように、AIは**研究成果物の生成**に長けていますが、100件すべてのテーマは人間が設計したものでした。

| 役割 | 担い手 | 本ベンチマークでの観察 |
|------|--------|---------------------|
| 課題設定・仮説構築 | 🧑‍🔬 研究者 | 100件すべて人間が設計。AIによるテーマ設定は未検証 |
| 文献調査 | 🤖 AI + 🧑‍🔬 研究者 | AIは候補文献の収集が可能。引用の正確性は未検証 |
| 実験設計・実装 | 🤖 AI（研究者監督下） | コード生成・パイプライン構築を自動化。実行検証は未実施 |
| 結果の解釈 | 🧑‍🔬 研究者 | AI生成の考察は表層的な傾向 |
| 論文執筆 | 🤖 AI + 🧑‍🔬 研究者 | ドラフト生成は可能。科学的推敲は研究者が必要 |

この前提のもと、AIの実行力を最大限に引き出すためのベストプラクティスを以下にまとめます。

## 1. プロンプト設計

### 1.1 3段階プロンプト構成を採用する

v1.0（単純な指示）からv4.0（3段階構成）への変更で、DOI付き引用が0件→16.3件に増加する相関が観察されました（ただし交絡要因は未制御）。以下の3段階構成を推奨します。

```
ステップ1: 先行研究調査
  └ 学術検索ツールで関連論文を5件以上調査
  └ 各論文のタイトル・著者・年・DOI・主要知見をまとめる
  └ 先行研究の課題・限界を整理する

ステップ2: 実験計画
  └ 先行研究の知見を踏まえた実験設計
  └ 先行研究との差分（改良点・新規性）を明確化
  └ ベースライン比較対象を先行研究から選定

ステップ3: 実験実施
  └ コード実装・可視化・レポート/論文生成
```

**効果**: 先行研究調査を前段に置くことで、AIが既存研究を踏まえた実験を設計できるようになり、引用の質と提案手法の位置づけが大幅に改善されます。

### 1.2 出力ファイルを明示的に指定する

AIに何を生成すべきか明確に指示しないと、出力の品質と一貫性にばらつきが生じます。

**推奨テンプレート**:

```markdown
最後に、以下のファイルを必ず作成してください：

1. **report.md** — 実験レポート
   - 実験目的と背景
   - 使用した手法の概要
   - 主要な結果（図を ![caption](figures/filename.png) で埋め込む）
   - 考察と今後の展望

2. **paper.md** — 学術論文形式
   - Title（英語）、Abstract（300語）
   - Introduction, Related Work, Methods, Experiments
   - Results, Discussion, Conclusion, References
   - 図を ![Figure N](figures/filename.png) で埋め込む
   - References には先行研究調査で発見した文献（DOI付き）を必ず含める
```

**100件の結果**: この指示により、report.md と paper.md の生成率は **100%** を達成。

### 1.3 研究要件を構造化して記述する

曖昧な指示ではなく、番号付きリストで具体的要件を列挙します。

**❌ 悪い例**:
```
CRISPR-Cas9のオフターゲット予測モデルを作ってください。
```

**✅ 良い例**:
```
CRISPR-Cas9のオフターゲット効果を予測するMLモデルを設計してください。
以下の要件を満たすこと：
1. ガイドRNA配列とゲノム配列のミスマッチパターンを特徴量として使用
2. エピジェネティクス情報（クロマチンアクセシビリティ、メチル化）を統合
3. Deep Learningアーキテクチャ（CNN+Attention機構）の詳細設計
4. 訓練データセットの前処理パイプライン
5. モデル評価指標（AUROC、精度-再現率曲線）と交差検証戦略
6. 臨床応用に向けた解釈可能性（SHAP値）の実装方針
```

**効果**: 要件を5-6項目に構造化することで、AIが各要件を漏れなく実装し、論文のセクション構成も自然に対応します。

### 1.4 引用の本文反映を明示的に指示する

v4.0の分析で、先行研究調査で得た文献がReferencesには記載されるものの、本文中のインライン引用が不足する傾向が観察されました。`[n]` 形式の引用は83件の論文で0件でした（ただし80件は `(Author et al., YYYY)` 形式を使用しており、引用形式が混在していました）。

**追加すべき指示**:
```
paper.md の Introduction, Related Work, Methods, Discussion の各セクションで、
先行研究調査で発見した文献を本文中で [1], [2] 等のインライン引用として参照すること。
参考文献は最低15件以上とし、そのうち先行研究調査で得た文献を5件以上含めること。
```

## 2. 実験管理

### 2.1 並列実行で効率化する

100件の実験の累積実行時間は約21時間（1,254分）ですが、5並列で実行した場合の実経過時間は約4時間39分でした。

| 並列数 | 推定所要時間 | 注意点 |
|--------|-------------|--------|
| 1 | ~35時間 | 安全だが非効率 |
| 3 | ~25時間 | バランスが良い |
| **5（推奨）** | **~21時間** | 最適。AIRAサーバーへの負荷が許容範囲 |
| 10 | ~15時間 | タイムアウトリスク増大 |

### 2.2 リトライ機構を組み込む

100件中9件（9%）が初回実行で失敗しました。失敗パターンと対策：

| 失敗パターン | 頻度 | 対策 |
|-------------|------|------|
| タイムアウト（>30分） | 4件 | タイムアウト閾値を3600秒に設定、自動リトライ |
| セッションエラー | 3件 | プロジェクト作成からやり直し |
| AI応答の途中停止 | 2件 | 完了判定ロジックの改善 |

**推奨**: メタデータに `status` フィールドを記録し、`status: 'success'` のみスキップするリトライ機構を実装。

```javascript
// リトライ判定
if (fs.existsSync(metadataPath)) {
  const meta = JSON.parse(fs.readFileSync(metadataPath));
  if (meta.status === 'success') {
    console.log(`  ⏭ skip (already done)`);
    return;
  }
}
```

### 2.3 メタデータを統一フォーマットで記録する

各実験の再現性と比較分析のために、統一されたメタデータを記録します。

```json
{
  "experiment_id": "SCI-001",
  "status": "success",
  "prompt_length": 1568,
  "output_length": 1617,
  "file_count": 24,
  "duration_seconds": 781,
  "timestamp": "2026-05-25T21:06:54.770Z"
}
```

**必須フィールド**: `experiment_id`, `status`, `duration_seconds`, `file_count`, `timestamp`

## 3. 品質評価

### 3.1 論文品質の定量指標

100件の分析から、以下の指標がpaper.mdの形式的特徴の把握に利用できることがわかりました。

| 指標 | 目標値 | v4.0平均 | 測定方法 |
|------|--------|---------|---------|
| 文字数 | 20,000-30,000 | 25,083 | `len(content)` |
| セクション数 (##) | 7-10 | 8.9 | `## ` の数をカウント |
| DOI付き参考文献 | 10件以上 | 16.3 | DOI正規表現でカウント（実在性未検証） |
| 本文中インライン引用 | 10件以上 | 3.0 ※改善余地 | `[n]` パターンをカウント |
| 数式数 | 20以上 | 45.6 | `$...$` パターンをカウント |
| 論文構成4要素 | 100% | 100% | Abstract/Method/Results/Conclusion の有無 |
| テーブル数 | 3以上 | 7.1 | マークダウンテーブルをカウント |

### 3.2 新規性マーカーの確認

[新規性マーカー分析](novelty-report.md)で使用した6基準スコアリング（8点満点）:

> **注**: これらは科学的新規性そのものではなく、「新規性を主張する修辞的要素」の有無を測定する形式的指標です。

| 基準 | 配点 | 説明 |
|------|------|------|
| 独自手法名の提案 | 2点 | 固有名詞付きの手法を提案しているか |
| 先駆性の主張 | 2点 | "to the best of our knowledge" 等の表現 |
| 複数技術の統合 | 1点 | 3つ以上のML/DL技術を組み合わせ |
| ベースライン比較 | 1点 | 既存手法との定量比較で優位性を主張 |
| DOI付き参考文献 | 1点 | 10件以上のDOI形式引用を含む（実在性は未検証） |
| 明示的貢献リスト | 1点 | Introductionで貢献点をリスト化 |

**分布**: 高（5+）39% / 中（3-4）31% / 低（0-2）30%

### 3.3 生成コードの品質確認ポイント

AIが生成するコードは構造的に妥当ですが、以下の点を研究者が確認すべきです。

| 確認項目 | よくある問題 | 確認方法 |
|---------|-------------|---------|
| データの実在性 | モックデータで代用されている | データソースのURL/パスを確認 |
| ハイパーパラメータ | 根拠なく設定されている | 先行研究の値と比較 |
| 評価指標の正当性 | 分野の標準と異なる場合がある | 分野の論文と照合 |
| ライブラリバージョン | 古いAPIを使用する場合がある | `pip install` で実行確認 |
| 乱数シード | 再現性のため固定が必要 | `random_state` / `seed` の設定確認 |

## 4. イテレーション改善

### 4.1 バージョン間比較で改善効果を測定する

4回のイテレーション（v1.0〜v4.0）の比較から得られた教訓:

| バージョン | 主な変更 | 効果 |
|-----------|---------|------|
| v1.0 → v2.0 | report.md/paper.md生成指示を追加 | 成功率95%→100%、出力長+20.8% |
| v2.0 → v3.0 | 論文構成の詳細指定を追加 | 出力長+24.9%、論文品質向上 |
| v3.0 → v4.0 | 先行研究調査ステップを前段に追加 | 所要時間-14.7%、DOI引用0→16.3件（相関。因果関係は未検証） |

**教訓**: プロンプトの改善は段階的に行い、各バージョンで100件の実験を実施して定量的に記録することが重要です。

### 4.2 プロンプト改善のPDCAサイクル

```
Plan  → プロンプトの仮説を立てる（例: 先行研究調査を追加すれば引用が改善するはず）
Do    → 100件の実験を実行する
Check → 品質指標を測定し、前バージョンと比較する
Act   → データに基づいてプロンプトを改良する
```

**測定すべき指標**:
1. 成功率（100%を維持しているか）
2. 平均所要時間（効率が落ちていないか）
3. 論文品質指標（文字数、引用数、構成要素）
4. 新規性マーカー（修辞的特徴）

## 5. 研究分野別の注意点

### 5.1 生命科学・バイオインフォマティクス

100件中、生命科学・バイオインフォマティクス関連のテーマが多数を占めています。特に注意すべき点：

- **データセット**: GUIDE-seq、CIRCLE-seq、TCGA等の公開データセットを具体的に指定すると、AIが適切な前処理パイプラインを設計する
- **倫理的配慮**: 臨床データを扱う実験では、プロンプトに倫理的考慮の記述を求めると論文の質が向上する
- **ツール指定**: BioPython、Scanpy、PyDESeq2等の分野標準ツールを明示すると、適切な実装が得られやすい

### 5.2 物理学・計算科学

量子化学、流体力学、天文学等の分野で注意すべき点：

- **数値精度**: シミュレーション系の実験では、数値精度の要件を明示する（倍精度、収束条件等）
- **計算コスト**: 大規模シミュレーションの場合、AIが生成するコードは概念実証（PoC）レベルであることを理解する
- **単位系**: SI単位系での一貫性を指示に含める

### 5.3 機械学習・データサイエンス

- **ベースライン**: 比較対象のモデル（Random Forest、XGBoost等）を明示的に指定すると、定量的な比較が充実する
- **可視化**: 「学習曲線、混同行列、ROC曲線を必ず生成すること」と指定すると、再現性のある図表が得られる

## 6. 既知の限界と対策

| 限界 | 説明 | 対策 |
|------|------|------|
| モックデータ依存 | AIは実データにアクセスできず、シミュレーションデータを使用 | 研究者が実データで再実行 |
| 組み合わせ的新規性 | 100%が既存手法の統合型。AIは組み合わせ的新規性の生成に長けるが、パラダイム転換的な着想は確認されていない | 研究者が独自の着想をプロンプトに反映し、AIの組み合わせ能力と相乗させる |
| インライン引用の不足 | 参考文献はあるが本文中での引用が少ない | プロンプトで明示的に指示（§1.4参照） |
| 長時間実験の不安定性 | 20分超の実験でタイムアウトリスク増大 | リトライ機構の実装（§2.2参照） |
| 結果の検証未実施 | 生成コードの実行結果は未検証 | 研究者が重要な実験を手動で再実行 |

## まとめ

AIRAを活用したAI for Scienceの成功は、以下の3つの原則に集約されます。

1. **研究者が問いを立て、AIが実行する** — 本ベンチマークでは100件すべてのテーマを人間が設計した。AIの問い設定能力は未検証だが、現時点では研究者の課題設定が出発点となる。
2. **プロンプトは実験の設計書である** — 3段階構成・構造化要件・出力指定の3要素を含むプロンプトが、より構造化された出力と相関した。
3. **定量的な観察サイクルを回す** — 100件規模のベンチマークで形式的指標を測定し、データに基づいてプロンプトを改善する。ただし、形式的指標は科学的品質の代替にはならない。

AIは科学研究の「成果物生成」を大幅に加速する可能性があります。しかし、生成物の科学的価値の評価は、研究者自身による批判的検討なしには行えません。
