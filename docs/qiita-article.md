## TL;DR

- AIエージェント「AIRA」に100の科学研究テーマを与え、文献調査→実験コード→論文を自動生成させた
- **100本すべてが12.5分で完成**。文献調査・コード実装・論文執筆の一貫ワークフローを完走した
- しかし生成された論文を分析すると、**100本中100本が「既存技術の新しい組み合わせ」** だった
- これは「限界」ではなく **「AIの本質的な強み」** だと気づいた——科学史上、多くのブレークスルーは既存手法の新しい組み合わせから生まれている
- 一方で、**「何を問うか」を決めたのは100本すべて人間** だった。AIは答えの生成に長けるが、問いの設計は（まだ）研究者の仕事である

---

## はじめに ── なぜ100本なのか

「AI for Science」という言葉を聞いて、あなたは何を想像するだろうか。

AlphaFoldによるタンパク質構造予測？ LLMによる論文要約？ それとも、AIが自律的に仮説を立て、実験し、発見する未来？

私が知りたかったのは、もっとシンプルな問いだった。

> **今のAIに「科学研究をしてください」と頼んだら、何が起きるのか？**

1本や2本では偶然かもしれない。10本でもパターンは見えにくい。だから **100本** やることにした。100本あれば、AIの得意なこと・苦手なこと・やらないことが、データとして浮かび上がるはずだ。

結果として得られたのは、AI for Scienceに対する楽観でも悲観でもなく、**「AIと研究者の分業モデル」の輪郭** だった。

## 実験セットアップ

### 使ったもの

| 項目 | 内容 |
|------|------|
| AIエージェント | AIRA (AI Research Assistant) ── ローカル実行 |
| 使用スキル | Co-Scientist（科学実験の自動実行を担当） |
| 学術検索 | ToolUniverse MCP（Semantic Scholar / PubMed / Crossref） |
| 自動化 | Playwright（5並列ワーカー） |
| 実行日 | 2026年5月25〜26日 |

### プロンプト設計（v4.0 / Round-9）

4回のイテレーションを経て到達した3段階プロンプト構成を使用した。

```
ステップ1: 先行研究調査
  └ ToolUniverse MCPで関連論文を5件以上検索
  └ 各論文のタイトル・著者・年・DOI・主要知見をまとめる

ステップ2: 実験計画
  └ 先行研究の知見を踏まえた実験設計
  └ 先行研究との差分（新規性）を明確化

ステップ3: 実験実施
  └ コード実装・可視化・レポート/論文生成
```

各テーマに対して、AIは以下を自動生成する:

- **Pythonコード**: データ前処理・モデル実装・学習パイプライン
- **図表（PNG）**: アーキテクチャ図・学習曲線・ベンチマーク比較
- **実験レポート（report.md）**: 目的・手法・結果・考察
- **学術論文（paper.md）**: Abstract〜Referencesを備えた論文形式文書

### 100のテーマ（抜粋）

| ID | テーマ |
|----|--------|
| SCI-001 | CRISPR-Cas9 オフターゲット効果予測ML |
| SCI-006 | AlphaFold2活用タンパク質-リガンド結合予測 |

| ... | *（全100テーマは[GitHub](https://github.com/nahisaho/aira_experiments)で公開）* |

テーマは生命科学・計算化学・物理学・データサイエンスなど多分野にわたる。

## 結果 ── 数字が語る100本の実態

### 全体サマリー

| 指標 | 値 |
|------|------|
| ワークフロー完了率 | **100%**（初回91%、リトライ後100%） |
| 平均所要時間 | **12.5分** |
| 累積実行時間 | 約21時間（5並列で実経過4時間39分） |
| 平均生成ファイル数 | 15.6 |
| paper.md 平均文字数 | 25,083 |
| DOI形式の参考文献 | 平均16.3件（97%の論文に存在） |
| 数式数 | 平均45.6個 |

**100本すべてが完走した。** 1本あたり平均12.5分で、文献調査・コード実装・図表作成・論文執筆を一気通貫で実行している。

### 所要時間分布

```
 5-10分  ████████████████████████████████████████████████████████  55件
10-15分  ████████████████████████  24件
15-20分  █████  5件
20-30分  ██████████████  14件
  >30分  ██  2件
```

55%が10分以内に完了。一方で、複雑なテーマでは30分超もある。

## 発見① ── 100本すべてが「組み合わせ的新規性」を持っていた

ここからが本題だ。

100本の論文（paper.md）を「新規性マーカー」で自動分析した。独自手法名の有無、先駆性表現、技術統合パターン、ベースライン比較などを抽出し、スコアリングした。

:::note warn
**注意**: このスコアは科学的新規性そのものではなく、「論文が新規性を主張するための修辞的要素」をどの程度含むかという形式的指標です。
:::

### 新規性タイプの分布

| タイプ | 件数 |
|--------|------|
| 統合パイプライン（複数技術の統合） | **100** (100%) |
| 手法融合（CNN+Attention等） | 99 (99%) |
| ベンチマーク比較 | 50 (50%) |
| 解釈可能性の付与 | 37 (37%) |
| 独自手法名の命名 | 31 (31%) |

**100本中100本が「統合パイプライン」型。** つまり、AIは一貫して「既存手法Aと既存手法Bを、ドメインCに適用する」というアプローチを取った。

最初、私はこれを「限界」だと思った。「結局AIは既存手法の組み合わせしかできないのか」と。

### でも、ちょっと待ってほしい

冷静に考えると、**科学研究の多くは「既存手法の新しい組み合わせ」で成り立っている。**

例えば、SCI-001が生成した「EpiCRISPR-Net」を見てみよう:

```
CNN（既存）+ Attention機構（既存）+ エピジェネティクスデータ（既存）
    → CRISPR-Cas9オフターゲット予測（新しい適用）
```

個々の技術はすべて既存だ。しかし、この3つを統合してCRISPRのオフターゲット予測に適用するという**組み合わせ自体は新しい**。これは多くの査読付き論文が持つ新規性の形態と同種のものだ。

つまり、AIの出力は「劣化コピー」ではなく、**「組み合わせ的新規性の高速生成」** と捉えるべきだったのだ。

100件を12.5分/本のペースで、それぞれ異なる技術の組み合わせを提案できる。人間の研究者が100通りの組み合わせを試行するには、何ヶ月もかかるだろう。

:::note info
**組み合わせ的新規性（Combinatorial Novelty）** とは、既存の手法・技術・概念を新しいパターンで組み合わせることで、個々の要素にはない新しい価値を生み出すこと。科学史上、多くのブレークスルーがこの形態の新規性から生まれている（例: PCR法 = DNAポリメラーゼ + 温度サイクル + プライマー設計）。
:::

## 発見② ── 「問い」を立てたのは100本すべて人間だった

もう一つの重要な発見がある。

100本の研究テーマはすべて人間（私）が設計したプロンプトに由来する。AIが自発的に「この問題を研究すべきだ」と判断した事例は **ゼロ** だった。

| 役割 | 誰がやったか |
|------|------------|
| 研究テーマの設定（What to solve） | 🧑‍🔬 人間（100/100） |
| 研究意義の判断（Why it matters） | 🧑‍🔬 人間 |
| プロンプト設計の改善方針 | 🧑‍🔬 人間 |
| 文献調査の実行 | 🤖 AI |
| 実験コードの実装 | 🤖 AI |
| 論文形式の文書作成 | 🤖 AI |

**AIは「どう解くか」には極めて有能だが、「何を解くか」は決めていない。**

ただし——ここは正直に言わなければならない——**本実験ではAIに研究テーマを設定させる実験を行っていない。** 「AIが問いを立てられない」と断定することは、本実験からはできない。これは今後の検証課題だ。

## 発見③ ── プロンプト設計で出力が劇的に変わる

4回のイテレーション（v1.0〜v4.0）で、プロンプト設計の影響を観察した。

| バージョン | 主な変更 | 観察された変化 |
|-----------|---------|-------------|
| v1.0 → v2.0 | report.md/paper.md 生成指示を追加 | 完了率 95%→100%、出力長 +20.8% |
| v2.0 → v3.0 | 論文構成の詳細指定を追加 | 出力長 +24.9% |
| v3.0 → v4.0 | 先行研究調査ステップを前段に追加 | DOI引用 0→16.3件、所要時間 -14.7% |

:::note warn
**注意**: これはランダム化比較実験ではなく、プロンプト以外の交絡要因は制御されていません。上記の変化は「観察された相関」であり、因果関係として解釈すべきではありません。
:::

特にv3.0→v4.0の変化は印象的だった。「先行研究を調べてから実験を設計せよ」という指示を追加しただけで、DOI形式の参考文献が0件→平均16.3件に増加した。しかも所要時間は14.7%短縮された（先行研究を把握した状態で実験に取り組むため、試行錯誤が減った可能性がある）。

**プロンプトは「指示」ではなく「実験の設計書」なのだ。**

---

## 発見④ ── 引用は「量」と「質」が乖離する

v4.0の論文を詳しく分析すると、興味深い問題が見えてきた。

| 指標 | 値 |
|------|------|
| DOI形式の参考文献 | 平均16.3件（97%の論文に存在） |
| 本文中のインライン引用 `[n]` | 平均3.0件（**83本は0件**） |
| Author-Year 形式 `(Author et al., YYYY)` | 80本が使用 |

Referencesセクションには16件以上の文献が並んでいるのに、本文中でそれらを引用している箇所が極端に少ない。**文献リストは「飾り」になりがちだ。**

さらに重要な点: DOIの実在性や引用内容の正確性は未検証だ。DOI形式の文字列が存在することと、その文献が実在し、正しく引用されていることは別問題である。

### 教訓

引用の質を上げるには、プロンプトで明示的に指示する必要がある:

```
paper.md の Introduction, Related Work, Methods, Discussion の各セクションで、
先行研究調査で発見した文献を本文中で [1], [2] 等のインライン引用として参照すること。
参考文献は最低15件以上とし、そのうち先行研究調査で得た文献を5件以上含めること。
```

## AI for Science の「本当の姿」── 私の理解

100本の実験を終えて、AI for Scienceに対する私の理解は次のように変わった。

### ❌ 以前の理解

> 「AIが科学研究を自動化する。いずれ研究者は不要になる」
>
> 「AIは既存手法の組み合わせしかできない。本質的な新規性は生まれない」

### ✅ 100本の実験後の理解

> **AIは「組み合わせ的新規性」の高速生成に長けている。** これは科学研究における正当な新規性の形態であり、AIならではの強みだ。しかし、「何を問うか」を決めるのは研究者の仕事であり、その問いの質がAIの出力の質を決定する。

**AI for Scienceは「革命」ではなく「共進化」だった。**

AIは研究者を置き換えるのではなく、研究者の「問い」を受けて、その解法空間を高速に探索する。研究者は、AIが生成した組み合わせの中から科学的に意味のあるものを見極め、実データで検証する。

```
研究者の問い（What）
    ↓
AIによる組み合わせ的探索（How）── 12.5分/本 × 100通り
    ↓
研究者による選別と検証（So What）
    ↓
科学的知見
```

この「問い→探索→選別」のサイクルこそが、AI for Scienceの本当の姿ではないだろうか。

## 実験の限界 ── 正直に書く

科学的誠実さのために、本実験の限界を明記する。

| 限界 | 影響 |
|------|------|
| **モックデータのみ** | 全データ・図表・数値はAI生成のシミュレーション。実験室での実測データは未使用 |
| **コード未実行** | 生成されたPythonコードが正常に動作するかは未検証 |
| **引用未検証** | DOI形式の文献が実在するか、引用内容が正確かは未確認 |
| **コントロール群なし** | 人間が同じテーマで書いた論文との比較がない |
| **単一実行** | 各テーマ1回のみ。LLMの確率的出力の再現性は未評価 |
| **交絡要因** | v1.0〜v4.0の比較でプロンプト以外の要因は未制御 |
| **問い設定の未検証** | AIに研究テーマを設定させる実験は行っていない |

**これらの限界があるからこそ、「AIが科学をできる」とは言わない。** 言えることは、「AIは研究成果物の生成ワークフローを完了し、組み合わせ的新規性を持つ文書を生成した」ということだけだ。

## 実践ガイド ── AI for Science をやるなら

100本の経験から、実際に試す人向けのアドバイスをまとめる。

### 1. プロンプトは3段階構成にする

```
先行研究調査 → 実験計画 → 実験実施
```

これだけで参考文献の充実度が桁違いに変わる（v3.0→v4.0で0→16.3件の変化が観察された）。

### 2. 出力ファイルを明示的に指定する

「論文を書いてください」ではなく、セクション構成・必要な図表・引用の形式まで指定する。AIは指示されたことは高い精度でこなすが、指示されていないことは省略しがちだ。

### 3. 100本規模で実行する

1〜2本では偶然と傾向の区別がつかない。100本やって初めて「AIのデフォルト行動パターン」が見える。5並列なら実経過5時間以内で完了する。

### 4. 結果を「科学的成果」として扱わない

AI生成物はあくまで「たたき台」。実データでの検証、コードの実行確認、引用の正確性チェックは研究者の責任。

### 5. 組み合わせ能力を活かす

AIの強みは、人間が思いつかない技術の組み合わせを高速に試行できること。100通りの組み合わせの中から、科学的に筋の良いものを選ぶ——これが研究者の新しい役割になりうる。

---

## まとめ

100本の実験を通じて、AI for Scienceの輪郭が見えてきた。

1. **AIは組み合わせ的新規性の生成に長けている** ── 100本すべてが複数技術を統合した新しいアプローチを提案した。これは科学における正当な新規性の形態だ
2. **しかし「問い」は人間が立てた** ── 100本すべてのテーマは人間が設計した。AIの出力の質は、研究者の「問い」の質に依存する
3. **プロンプト設計で出力は劇的に変わる** ── 3段階構成の導入でDOI引用が0→16.3件に変化（相関）
4. **AI for Scienceは「共進化」である** ── AIが研究者を置き換えるのではなく、研究者の問いをAIが高速に探索する分業モデルが浮かび上がった

**AIに100本の論文を書かせてわかったのは、AIの能力ではなく、研究者の「問い」の重要性だった。**
